# Build & Flash — Wallbox-Local (Shelly 1PM Gen1)

> Target: **Shelly 1PM Gen1** (ESP8266 + HLW8012/BL0937), Mongoose OS.
> App name stays `Wallbox-Shelly1PM` so the stock OTA endpoint accepts the package.
> Verified working on 2026-09-02 (Batch B + C + finding #7).

## 0. Prerequisites (one-time)

- **WSL2** (Ubuntu) with **Docker** running. The Windows Git Bash shell has no
  `docker` binary; all builds run inside WSL.
- Node.js >= 18 and npm inside WSL (used to build the Web UI).
- The Mongoose OS build image cached locally:
  ```bash
  docker images | grep mgos
  # expected: mgos/mos:latest  (reference build image)
  ```
  If missing: `docker pull mgos/mos:latest`
- Mongoose OS public download servers are **down (404)**. Only `mos build --local`
  (compile inside the container) works. Do not use remote build.

Repository path (Windows) : `C:\Users\I058304\HomeAssistant\shelly-ocpp-wallbox`
Same path seen from WSL    : `/mnt/c/Users/I058304/HomeAssistant/shelly-ocpp-wallbox`

## 1. Build the Web UI (produces `dist/`)

The firmware bakes `dist/` (Web UI) **and** `fs/` (hand-authored FS files, incl.
`rpc_auth.htdigest`) into the SPIFFS image. `dist/` is regenerated by webpack and is
gitignored; `fs/` is versioned. Never put a source file only in `dist/` — webpack
wipes it (`clean: true`).

```bash
wsl -e bash -lc 'cd /mnt/c/Users/I058304/HomeAssistant/shelly-ocpp-wallbox && npm install && npm run webpack'
```

Output: `dist/index.html.gz` (single self-contained gzipped page) + `dist/favicon.png`.

## 2. Build the firmware (produces `build/fw.zip`)

The nested Windows -> WSL -> bash -> docker -> sh quoting is fragile. Use a tiny
build script inside the repo to avoid quote-escaping hell:

```bash
wsl -e bash -lc '
R=/mnt/c/Users/I058304/HomeAssistant/shelly-ocpp-wallbox
cat > "$R/_build.sh" <<SH
#!/bin/sh
set -e
git config --global --add safe.directory "*"
mos build --local --platform esp8266
SH
chmod +x "$R/_build.sh"
docker run --rm --entrypoint /bin/sh \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v "$R:$R" -w "$R" \
  mgos/mos:latest "$R/_build.sh"
rm -f "$R/_build.sh"
'
```

Success line: `Firmware saved to .../build/fw.zip`
Expected size: ~905 KB (`fw.zip`), `fs.bin` = 262144 bytes.

`git config --global --add safe.directory "*"` is required because the repo lives on
the Windows-mounted filesystem (`/mnt/c`), which the container sees as a different
owner — without it `mos build` aborts on "dubious ownership".

## 3. Verify the package (before flashing)

Confirm the credential file and Web UI are actually inside the SPIFFS image:

```bash
wsl -e bash -lc '
R=/mnt/c/Users/I058304/HomeAssistant/shelly-ocpp-wallbox
cd "$R" && rm -rf /tmp/fwcheck && mkdir /tmp/fwcheck && unzip -o build/fw.zip -d /tmp/fwcheck >/dev/null
BIN=$(find /tmp/fwcheck -name fs.bin)
echo "fs.bin: $BIN"
strings "$BIN" | grep -E "rpc_auth.htdigest|admin:wallbox:|index.html" || echo "MISSING FS CONTENT"
'
```

Expected: `rpc_auth.htdigest`, `admin:wallbox:<md5>`, and `index.html.gz` all present.

Optional structural diff against a known-good baseline:
```bash
wsl -e bash -lc 'cd /mnt/c/Users/I058304/HomeAssistant/shelly-ocpp-wallbox && python3 scripts/compare_fw.py <baseline.zip> build/fw.zip'
```

## 4. Flash / Update the device

### 4.a OTA via the Shelly's current Web UI (recommended)

The device is already running our firmware, so update over the network.

**IMPORTANT — RPC auth is now enabled (Batch B).** The `/update` endpoint and all
`/rpc/*` calls on HTTP now require HTTP Digest auth (user `admin`, realm `wallbox`).
There is **no default password**: the credential file `fs/rpc_auth.htdigest` is
generated locally before the build (`npm run gen-htdigest`, needs
`WALLBOX_ADMIN_PASS`). See README §1-quater "Identifiants Digest".

- Browser: open `http://<wallbox-ip>/` (or `http://wallbox.local/`), the browser
  prompts for credentials. Use the firmware-update file picker, choose `build/fw.zip`.
- Or curl:
  ```bash
  curl -v --digest -u admin:<password> -F file=@build/fw.zip http://<wallbox-ip>/update
  ```
  Note `--digest` (not basic). The device reboots on success.

### 4.b Initial serial flash (only for a stock Shelly, first time)

Requires a USB-to-TTL adapter wired to the Shelly. UART/serial RPC is left open
(no auth) by the ACL, so `mos` over serial needs no credentials.

```bash
mos --port COM8 flash            # Windows COM port
# or inside WSL with the adapter passed through:
mos --port /dev/ttyUSB0 flash
```

## 5. Post-flash sanity check

```bash
# GetInfo now requires auth:
curl --digest -u admin:<password> http://<wallbox-ip>/rpc/Wallbox.GetInfo
# UART is open; over serial no auth needed:
mos --port /dev/ttyUSB0 call Wallbox.GetInfo
```

Confirm: `app: "Wallbox-Shelly1PM"`, correct `version`, `mqtt_user` **absent** from the
response (removed by finding #7).

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `unexpected EOF while looking for matching '` | nested quote escaping | use the `_build.sh` pattern in §2 |
| `fatal: detected dubious ownership` | repo on `/mnt/c` | keep the `safe.directory "*"` line |
| `/update` returns 401 | Batch B auth enabled | add `--digest -u admin:<password>` |
| Web UI loads but all fields empty / errors | app.js RPC calls get 401 | expected until L2-B adds front auth |
| `docker: command not found` | running in Git Bash, not WSL | prefix everything with `wsl -e bash -lc` |
